# Android camera return regression
Physical Android feedback: selecting Take new photo launches the camera, but returning resets the Body Photos option and no preview appears. Source inspection found that any SIGNED_IN event set global isLoadingAuth=true, causing AuthenticatedApp to replace all routes with a spinner and destroy the local photo state. Supabase may emit SIGNED_IN when a session is reconfirmed on browser focus. This is a concrete reset path consistent with the reported symptom; actual event sequence has not been captured on the phone.
Same verified account events now run a server identity check without unmounting routes. Sign-out, missing identity and different account events clear or block the UI, and stale asynchronous verification is ignored. Routes are keyed by authenticated account. Private photo upload flags, temporary memory cleanup on real pagehide/unmount, original capture file validation and existing privacy boundaries are unchanged. No database or external service changes.
Retest native camera and gallery with synthetic/non-sensitive photos, confirm selected view and consent remain, counter increments, other views retain their previews, and removal/navigation/sign-out clear them. If Android discards/reloads the browser document, in-memory images cannot be recovered; do not silently persist sensitive files. If the reset persists, investigate actual page lifecycle and consider a consented in-page camera path. Verify login/logout, account switching and failed authentication separately. Unit checks do not substitute for physical Android verification.
