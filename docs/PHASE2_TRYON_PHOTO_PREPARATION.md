# Customer photo preparation — Phase Two
Local-only shopper UI. No upload, provider request, backend change, stored photo access or fit claim. Consent is per component session; selection requires opt-in. JPEG/PNG only, 10 MiB maximum, minimum 480 px each side, maximum 8192 per side and 24 megapixels. Header format/dimensions checked before browser decode; animated PNG rejected. Browser decode and bounded 1200-pixel canvas JPEG preview remove original metadata from the displayed copy. Generation tokens discard stale results; removal, consent withdrawal, product change, route unmount and pagehide clear the preview and revoke its object URL. Original gallery photo is unchanged. No persistent consent or photo data.

These thresholds are provisional. The basic checks do not detect pose, blur, lighting, person identity, multiple people or garment suitability. Actual Android camera/gallery behavior and memory performance require device testing. Browser decode can still temporarily allocate memory; generation tokens prevent stale display but do not abort browser decoding. No server-side photo consent, retention, access or deletion contract is activated. Do not connect to a provider until commercial clearance, real renderer evaluation, explicit external-processing consent and private storage controls are complete. Keep retailer asset review and size-chart guidance separate.
